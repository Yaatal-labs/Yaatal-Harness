00 In one breath

The thesis Yaatal is a sovereign, edge-to-cloud AI platform for African (Wolof/French-first) commerce and assistance, built constraints-first — cheap phones, weak networks, battery, code-mixed speech, low-resource data, trust-sensitive money. Its defining primitive: models propose, the Engine disposes — AI may suggest an action, but only the sovereignty-typed Engine turns intent into a real effect (money, orders, PII), and Sovereign data is enforced at compile time to never leave Senegal. BOBO is the first app surface, not the point.

01 The layered architecture — read this first

Yaatal is not one monolith — three layers plus an R&D lane. This manifest is the Engine (runtime) view; the Harness has its own. Dependency is one-way: Engine depends on Harness, not the reverse.

Dependency

Engine provides verified user/session/profile context and calls Harness pipelines through explicit Rust contracts.

Boundaries

Harness never owns auth/profile/transport/routes/deploy. Engine never owns app UX. Apps never duplicate AI reliability logic.

Promotion

One app needs it → app. Two apps → Engine. Unproven AI → R&D Harness. Proven AI reliability → Runtime Harness.

Alignment in progress: the Engine repo still holds its own copies of capability crates (ai, search, feed, voice). Target: Harness-owned, Engine-consumed. The name collisions + dependency direction are an active task, not the finished state.

03 Prime directives

Layer boundaries

Apps / Engine / Harness, dependency one-way. Keeps the platform from becoming three competing systems; capabilities are proven in R&D and promoted when hardened.

Sovereignty is a type, not a setting

Residency to Senegal / Diamniadio must be un-bypassable. In the type system, the compiler is the auditor.

African-first economics & networks

Metered compute, expensive/intermittent bandwidth, constrained devices. Prefer cheap/local/edge before frontier/cloud; degrade gracefully.

Promotion over duplication

App → Engine → Runtime Harness is a one-way ratchet earned by proof, not copy-paste. Nothing hardcoded in Rust.

04 Subsystem manifest — choice by choice

4.1

Loco — "Rust on Rails"

EngineV1
What
Batteries-included Rust web framework: routing, sea-orm, workers, mailers, JWT auth.
Why
Ship product, not plumbing, in a memory-safe, no-GC, low-footprint language; Rust's types enable the sovereignty spine.
Rejected
Axum-from-scratch (boilerplate); Node/Python (footprint, GC, weaker guarantees).
Is not
A microservice swarm. One runtime binary.
4.2

Sovereignty type system

Shared coreV1
What
Sensitivity { Sovereign · Operational · Public }, a sealed SensitivityTag, phantom-typed Tagged<T,S>. Sovereign = stays in Diamniadio Postgres, never mirrors to edge.
Why
Residency is a first-class invariant; sealing makes misclassification a compile error.
Rejected
Runtime checks / config flags (bypassable, drift, fail open).
Is not
A GDPR checkbox.
4.3

Tag-gated storage

Shared coreV1
What
StorageDispatcher<T,S> over memory · postgres · r2. R2 only implements …<T,Public> — a Tagged<T,Sovereign> to R2 does not compile.
Why
The edge is Public-by-construction; sovereign data physically cannot route there.
Is not
A place sovereign data can escape to the CDN.
4.4

Persistence — sea-orm + migrations

EngineV1
What
Typed models, migrations-as-code, applied on boot.
Why
Versioned, reviewable, self-applying schema; no manual prod DDL.
Is not
Drift-safe by accident. Scar: a uuid column bound as String passed every SQLite test and 500'd on Postgres (42804/42883); fixed uuid→text. Green-on-SQLite ≠ green-on-Postgres.
4.5

Auth · commerce · profile identity

EngineV1
What
JWT auth, profile resolution, BOBO commerce bridge (orders, checkout, KYC, escrow, merchant).
Why
This is the "disposes" half — verified context + execution that validates before anything real happens. The right home for future AI-proposed actions.
Is not
App UX — app-agnostic primitives (the named BOBO bridge is the one deliberate seam).
4.6

Payments

EngineV1 partial
What
Normalized contract + RailSelector + idempotent EventStore + webhook router. Wave real (HMAC-SHA256); others stub RailNotConfigured.
Why
African payment fragmentation behind one contract; idempotent webhooks.
Roadmap
bobo_checkout writes intents via raw SQL — two paths to converge.
4.7

LiveKit — real-time control plane

EngineV1 control / ROADMAP media
What
Engine mints join tokens + receives webhooks; media flows client ↔ SFU. Unconfigured → 503.
Why
Engine owns auth/control, not the media path (latency/cost/scale).
Is not
A media server.
4.8

AI cascade router

Harness (in Engine today)V1 orchestration / ROADMAP inference
What
Data-driven 5-tier router (Tier 1 on-device → SiliconFlow → OpenRouter → HF) via reqwest. Guards: circuit breaker · network gate · rate limit · task classify (FR/EN) · sensitivity routing.
Why
Cost + sovereignty + resilience — cheapest/local first, frontier last; sensitive prompts off third-party clouds; degrade, don't crash/overspend. Provider-swappable.
Status
Orchestration real but does no inference; Tier 1 is a placeholder ("…local GGUF in E7"); no keys → AllTiersExhausted. Target home: Harness.
Is not
A thin proxy — a resilient, policy-/network-aware router.

06 On-device — phase E7 ROADMAP

Track A · engine-side

Sovereign / self-hosted inference

Fill the Tier-1 placeholder so Sovereign prompts are answered without leaving Diamniadio. Runtime: candle / llama-cpp-2 / mistral.rs / ort; small quantized GGUF; feature-gated; RAM/CPU budget. Payoff: sensitive inference never touches a foreign cloud.

Track B · app-side

True phone-side inference

A model on the user's device in BOBO native (ExecuTorch / MLC / llama.rn) — offline-first, the literal cheapest tier; Engine becomes the cloud fallback. App work, not Engine work. Where LFM2.5-Audio lands.

09 The two clocks — how to read all of the above

Fast · shippable now

Platform clock

Engine → SDK → spin → scaffold, compounding today. Uses off-the-shelf cloud AI for near-term product value. This is the fastest path.

Slow · high ceiling

Research clock

The sovereign Wolof model program. De-risked in the R&D Harness, promoted only when hardened.

The readThe architecture (R&D Harness + promotion rule) is literally designed to run both clocks without merging them. Ship the spine on the platform clock; let the ceiling arrive on the research clock. Today: an R&D project with a production-grade spine and a defensible research thesis — a rare and strong position, as long as the framing stays honest.
